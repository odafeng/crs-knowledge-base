# 0022. 回訪以「送到醫師手上」為主，自由論壇設開放門檻

**Status**: Accepted（2026-11-17 維護者確認；Job G、H。同日修訂：論壇提前開放，見 H4 #126）

## Context

維護者希望大腸直腸外科醫師願意經常使用 GutHub，並問是否加入自由論壇：讀者可以自由開話題、按讚、回應，也能用自然語言搜尋最相關的討論串。

實證不會每天更新。為了「每天都來」而硬塞內容，反而讓網站顯得稀薄。台灣醫師每天開的是 LINE，不是網站；最能吸引他們回來的資訊，是 NCCN、UpToDate 沒有的台灣健保給付與 TFDA 核准異動。

自由論壇有三個風險：
- **冷啟動**：大腸直腸外科圈子小，空的論壇會傷信譽。
- **隱私與法規**：病例討論容易帶到可識別病人的資訊；公開討論特定處方藥，可能碰到藥品廣告規範。這是判斷，不是法律意見，開放前應另行確認。
- **審核負擔**：依 ADR-0017，管理者只有維護者一人。

## Decision

- **回訪（Job G）**：把內容送到醫師手上，目標是「每次打開都有收穫、需要決策時第一個想到」，不追求每日人數。具體做法：
  - LINE 官方帳號每天早上推送一則，沒有新內容就不推。
  - 首頁「今天的一件事」。
  - 健保／TFDA 異動監測：有變動時開 review issue，經人確認才改卡片。
  - 主題訂閱、tumor board 一頁摘要、追蹤文獻討論的通知、會議季每日速報。
  - 以伺服器端彙總的每週回訪率衡量，不用第三方追蹤。
- **可以先做的部分（Job H）**：
  - 文獻留言加按讚。
  - 自然語言語意搜尋：先涵蓋公開的文獻、消息與治療卡片，embedding 供應商與費用上限由維護者決定（H2）。
  - **H2 決定（2026-11-17）**：embedding 用 Voyage AI 的多語言模型，每月費用上限 USD 5；型號是 `voyage-4`（多語言，1024 維，每百萬 token USD 0.06，上限折合每月 8,000 萬 token，由索引與查詢共用）。H3 實作（2026-11-18）：每篇文獻、每則消息、每張治療與機器手臂卡片各一段，內容變了才重送；查詢用 POST 傳，不進請求紀錄；相似度低於 0.35 不列為結果，問到站上沒有的題目就回「沒有足夠相關的內容」，不硬湊。門檻依實測決定：完整句子的最高分 0.50–0.66、簡短關鍵字 0.39–0.44、無關問題最高 0.26。送到 Voyage 的內容是公開的文獻、消息、治療卡片，以及論壇話題與回覆（H8，不帶作者資訊）。論壇討論串只出現在已驗證大腸直腸外科會員的搜尋結果裡，其他人只搜得到公開內容。H8 實作（#130，2026-11-18）：每篇已公開的話題與回覆各算一段，內容是話題標題加貼文本文，跟著每天的 search-index job 更新，所以新貼文最晚隔天才搜得到。查詢時再對照一次目前公開的貼文，被隱藏或刪除的會立刻從結果消失。同一串只列一次，最多 4 串，和證據分開列。登入的讀者搜尋時會帶上登入憑證，API 只用它判斷是不是會員。查詢文字不與帳號綁定保存。首頁放自然語言搜尋入口。
- **自由論壇設開放門檻**：上線後依實際討論量決定（H4）。agent 建議的門檻是「連續 4 週、每週至少 10 位不同讀者留言」，並只限驗證過的醫師、禁止可識別病人的資訊。門檻達成並由維護者確認後，才實作醫師驗證、討論串與論壇介面，語意搜尋再擴及討論串（H5–H8）。

### LINE 推送（2026-11-17 維護者決定；G1 #112）

- **方案**：先用免費的輕用量（每月 200 則），接近上限再升級中用量（每月 1,000 元未稅、3,000 則）。訊息按收件人計算，推一則給 N 位追蹤者就算 N 則；Messaging API 的推送與官方帳號後台的群發共用這個額度。
- **頻率**：有新內容才推，一天最多一則，內容用 G2 的每日挑選（`GET /api/v1/daily-pick`）；當天沒有新內容就不推，不用「最近的一件事」補位。
- **帳號**：另外建立給讀者的「GutHub」官方帳號，由維護者擁有。Paper Watch 通知維護者自己的既有帳號維持不變，兩邊的額度與追蹤者互不影響。agent 只拿新帳號的 Messaging API channel access token，存放在 Secret Manager。
- **實作（G3 #114）**：每天 07:00 的 Cloud Run job 用 Messaging API 的 broadcast 發送前一天的挑選；Paper Watch 在 16:00 發布，只有隔天早上的推送帶得到這些論文。job 先在 `app.line_broadcasts` 佔下當天並存一個 retry key，重試都沿用同一個 key；LINE 對已接受過的 key 會回 409，所以就算 job 在 LINE 收下後、記錄前中斷，重跑也不會重複發送。
- **會議季（G9 #120）**：在 Paper Watch 每日掃描的會議期間內（`scripts/queries.json` 的 `conference_seasons`），同一則訊息改列出前一天新增的全部文獻與消息，最多 5 則，順序與每日挑選相同，其餘附「全部更新」連結；仍是一天最多一則。API image 只含 `apps/api`，所以期間另存一份 `guthub_api/conference_seasons.json`，由 `refresh_conference_dates.py` 一起更新，測試確保兩份一致。

### 主題篩選、留言通知與第一批討論者（2026-11-20 維護者決定）

- **LINE 不依主題篩選**（G6 #117）：每月最多約 8 則，篩選的好處小，卻要多存一份「LINE 使用者 ID → 主題」的個人資料，還要從 broadcast 改成逐人 multicast。LINE 維持發給全部追蹤者。帳號頁的主題訂閱只用在網站本身（PR #155，首頁在瀏覽器端列出「你訂閱的主題」）。
- **追蹤文獻的新留言用 Email 每日彙整通知**（G8 #119）：每天最多一封，列出你追蹤的文獻各有幾則新留言與連結；信中不出現任何留言者的名稱，署名的也不列。信件附一鍵取消追蹤與退訂連結，用已驗證的 Resend 寄送。推播維持不連到帳號（ADR-0023），隱私權政策對推播的承諾不變；新增的個人資料是「帳號 → 追蹤的文獻」，要寫進隱私權政策。
- **第一批討論者**（G11 #122）：維護者私下邀請 5–8 位信任的同事，在正式上線後 2 週內完成；issue 只記人數與時間，不寫姓名。

### 論壇提前開放（2026-11-17 維護者決定；H4 #126）

維護者決定不等門檻，現在就做論壇。上面「自由論壇設開放門檻」一節因此不再適用：

- **三層身分**（同日維護者補充）：
  - **非會員**（未登入）：閱讀公開內容，不能留言。
  - **一般會員**（登入）：文獻頁留言、按讚、訂閱主題與推播。
  - **大腸直腸外科會員**（驗證過）：另外可以進論壇。論壇整個不公開：非會員與一般會員都看不到內容，搜尋引擎也不收錄。
- **誰是大腸直腸外科會員**：大腸直腸外科專科醫師，以及正在受訓的住院醫師與 fellow。維護者人工核對（H5）：專科醫師對照大腸直腸外科醫學會的公開名單；受訓醫師對照衛福部醫事人員查詢與執業院所。申請人填真實姓名、執業院所與證書字號後三碼（原本還有科別，2026-11-18 維護者決定拿掉：會來申請的一定是大腸直腸外科），不收文件，也不收身分證字號（外洩後無法更換，雜湊也擋不住暴力反推，維護者也沒有可對照的資料）；審核完刪除姓名、院所與證書號碼，只留驗證狀態、時間與核准者。
- **病例討論規則**：維持原本的建議。禁止可識別病人的資訊與影像，發文前顯示提醒（H7）。
- **自動審核**（同日維護者補充，H10）：符合兩個條件就自動核准，不等維護者。第一，姓名與執業院所對得上大腸直腸外科醫學會官網公開的「醫師地圖」。第二，登入信箱屬於該院的網域（例如臺北榮總的 `vghtpe.gov.tw`）。只對姓名和院所不夠，因為兩者都是公開資料，任何人都能冒用；信箱已經過登入驗證，能證明申請人確實在那家醫院。缺任一項的申請照舊進維護者的審核頁，頁面先標出「醫師地圖有此人」或「查無」。醫師地圖約 235 人，少於 550 多位會員，也沒有受訓醫師，所以人工審核仍會持續。名冊只在送出申請和開審核頁時即時查詢，不另存第三方的姓名資料。曾被退回或撤銷的帳號一律回到人工審核。自動核准有開關（`GUTHUB_SURGEON_AUTO_APPROVE`，部署時由 production environment 的變數 `SURGEON_AUTO_APPROVE` 控制），要先在 Supabase 開啟 email confirmations 才能打開（2026-11-18 維護者決定開啟，H11 #172）：關閉時改信箱不必確認新地址，登入後再把信箱改成醫院網域，token 上的信箱就證明不了什麼。只認收信登入（amr 為 otp 或 magiclink）也是同樣的理由，密碼註冊不必收信。
- **論壇資料與 API**（H6 #128，2026-11-18 實作）：話題與回覆放在同一張表，話題就是一串的第一篇，只有它帶標題，以及連結的主題或文獻。連結的文獻撤下後就不再顯示連結。留言的規則全部沿用 ADR-0017：署名或匿名、私有的作者對應、帳號第一篇先審、軟刪除、刪除 90 天後清除作者對應，發文頻率上限也和留言相同（論壇另外計數）。有一點不同：已經有留言通過審核的帳號，第一篇貼文不必再審。每篇上限 5,000 字（留言是 2,000），病例討論需要較長的篇幅；標題上限 120 字。不是會員的人，不論是否登入，所有論壇 API 都回 404。刪掉或隱藏第一篇，整串一起消失。置頂與查閱匿名作者在 H7 補上。
- **論壇介面與審核**（H7 #129，2026-11-18 實作）：導覽列有「論壇」，帳號頁的會員區塊也有入口；非會員點進來只看到誰能加入、怎麼申請。發話題和回覆前都要勾選「內容不含可識別病人的資訊」，旁邊列出不能貼的東西：姓名、病歷號、身分證字號、生日、確切就診或手術日期、照片與影像。論壇頁面一律 noindex（meta 與 `X-Robots-Tag` 都有），`Cache-Control: private, no-store`，service worker 不存，也不進 sitemap 與站內搜尋；HTML 裡沒有任何論壇內容，話題標題也不寫進網頁標題。維護者不必是會員也能審核：審核頁列出待審和被檢舉的貼文，以及全部話題，可以公開、隱藏、置頂；置頂、取消置頂、查看匿名作者都要寫原因並記錄。作者看得到自己還在等審核或被隱藏的貼文，也可以刪掉。置頂的話題只在第一頁另外列出，往下翻頁時不會重複或漏掉。
- **冷啟動**：用 AI 開第一批話題（H9）。AI 話題一律以標明為 AI 的站方帳號發出，不冒充醫師，也不虛構病例或經驗；內容只取自站上已整理的實證（文獻條目、治療卡片、健保／TFDA 異動），並附上來源連結。和網站其他 AI 內容一樣標示「AI」。實作（H9 #161，2026-11-18）：AI 話題不屬於任何帳號，署名「GutHub AI」，貼文帶 `ai` 標記，論壇頁面顯示 AI 標籤。草稿放在 `data/forum_ai_topics.json`，維護者逐則看過、把 `approved` 改成 true 之後，`scripts/forum_ai_topics.py` 才會以內容擁有者身分發出；同一個標題不會重複發。API 角色只拿得到它會寫的欄位，無法把貼文標成 AI。AI 話題發出就公開，因為草稿已經審過；沒有人能透過 API 修改或刪除，要撤下就由維護者隱藏。每則結尾註明是 AI 依站上實證開啟、數字照抄條目、不是臨床建議。**H9 決定（2026-11-18）**：維護者核准 7 則草稿全部發出，並要求語氣更像人；改寫後數字、給付規定與出處不變（PR #187）。2026-11-18 已發到 production：7 則發出，0 則略過。**修訂（2026-11-19，維護者決定）**：這 7 則改由維護者具名，作者改成維護者本人的帳號，拿掉 `ai` 標記與結尾的 AI 說明，用來帶動發文風氣。內容是維護者逐則審過、採用的稿件，所以視為維護者本人的貼文；不建立虛構的醫師身分。這是對「AI 話題一律標示 AI」的例外，只適用於這 7 則；`scripts/forum_ai_topics.py` 之後發的話題仍然標示 AI。

## Consequences

- 先用成本低、立即有價值的功能（LINE 推送、給付異動、按讚、文獻語意搜尋）累積習慣，論壇是否值得做，由實際數據回答。
- 喜歡自由討論的讀者，在論壇開放前只能在文獻頁留言，話題受限於既有文獻。
- LINE 推送依賴官方帳號方案，追蹤人數增加後要付費：免費額度在每月推 8 次時約夠 25 人，達到上限後當月就推不出去，得在 G10 的每週活動看到成長時提早升級；語意搜尋要把公開內容送到第三方 embedding 服務，需在隱私權政策揭露。
- 若論壇開放並限驗證醫師，需要人工審核醫師證明，增加維護者的工作量與個資保管責任。
- 門檻是 agent 的建議數字，不是驗證過的標準；H4 決定時可依實際情況調整。
- 自動審核擋不住同院的冒用：持有該院信箱的人，填同院另一位醫師的姓名仍會通過。風險限於院內，事後可由維護者撤銷。醫院與網域的對照表要人工維護，醫學會改版醫師地圖時，比對會失效並全部退回人工審核，不會誤放。
- Voyage 是付費服務且會收到論壇內容；超過每月上限時，語意搜尋停用並退回關鍵字搜尋。
- 提前開放後，冷啟動的風險改由 AI 話題承擔。AI 話題能讓論壇不是空的，但醫師一眼就看得出哪些是 AI 開的；如果只有 AI 話題、沒有醫師回覆，空的感覺仍在，所以 G11 邀請第一批討論者仍然需要。人工審核醫師證明的工作量與個資責任，從「門檻達成後」提前到現在。
